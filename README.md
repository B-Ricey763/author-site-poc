# Serial Author Site — proof of concept (v2, Hugo)

A **stylistically neutral** static site for an aspiring fantasy author
to publish a novel **free, chapter by chapter**, build a following, and
(hopefully) attract a traditional publishing deal later — the Andy Weir
model.

Built with [Hugo](https://gohugo.io/) so the author never touches HTML:
**every page and chapter is a plain Markdown file.** Design is
deliberately plain — clean serif reading typography, light/dark aware,
nothing branded.

> **New here? Read [`EDITING.md`](EDITING.md)** — the non-technical
> guide to publishing chapters from the GitHub website, or by handing
> this repo to an AI agent (see [`AGENTS.md`](AGENTS.md)).

## What's in v2

- **Home** — book pitch, start reading, latest chapter, full chapter
  list, email signup block, RSS link
- **Contents** (`/chapters/`) — auto-generated from the chapter files
- **Reader** — one page per chapter: clean typography, reading progress
  bar, prev/next chapter, text-size toggle
- **About** — author bio + how the serial works
- **RSS + sitemap** — generated by Hugo automatically
- **Sample content** — placeholder author ("Your Name") and placeholder
  fantasy novel *The Ashen Gate* with 3 short sample chapters, so the
  reading experience can actually be judged

## Publish a chapter (short version)

Add one Markdown file to `content/chapters/` (template in
`archetypes/chapter.md`, full walkthrough in `EDITING.md`), commit,
push. GitHub Actions rebuilds and deploys the site automatically.
Settings (author name, book title, cadence) live at the top of
`hugo.toml`.

## Run it locally

```bash
hugo server   # preview at http://localhost:1313
hugo          # build into ./public
```

## Deploy

Push to GitHub, then in the repo: **Settings → Pages → Build and
deployment → Source: GitHub Actions**. The workflow in
`.github/workflows/hugo.yml` (Hugo 0.170.1) does the rest. The site can
also be built and hosted on Cloudflare Pages / Netlify with no changes.

## Known placeholders / decisions waiting on feedback

- Email form is inert until a service is chosen — set
  `newsletterAction` in `hugo.toml` (Buttondown, ConvertKit, ...).
  Owning the email list is the single most valuable asset this site
  can build.
- Author name, book title, blurb, and the 3 sample chapters are
  placeholders.
- `baseURL` in `hugo.toml` is `example.org` until a real address exists.
- No comments, analytics, accounts, paywall, or Patreon integration —
  each is a decision, not a default.
